# 街角记忆 · Street Corner Memories

> 在这个点外卖、叫维修、去网红理发店的年代，你有多久没有好好看过一条老街了？

一条老街上藏着六位手艺人。他们不在招牌上，不在菜单里，只在各自店铺的深处。
初始时街上只有六个微微发光的呼吸点——**找到他们，点一下，他们就会走出来跟你说话**。

## 核心机制

### 1. 坐标系绑定背景图（重要，改坐标前必读）

`data.js` 里角色的 `px / py / ph` **不是舞台百分比，而是背景图 `bg-street.jpg` 自身的百分比**。

原因：背景图用 `object-fit: cover`，舞台宽高比一变，背景就等比缩放 + 居中裁切，
**图像内容在舞台里的位置会跟着移动**。如果人物按舞台百分比定位，缩放一变化就和店铺脱节了。

`app.js` 的 `layout()` 负责复现 cover 映射，把背景图坐标换算成舞台像素：

```js
const fitScale = Math.max(w / iw, h / ih);          // cover 取 max
const dispW = iw * fitScale, dispH = ih * fitScale;
const cropX  = (w - dispW) / 2;                    // 居中裁切的水平溢出（负=左右被切）
const cropY  = (h - dispH) / 2;
const bx = u => cropX + (u / 100) * dispW;         // 背景图% → 舞台px
const by = v => cropY + (v / 100) * dispH;
const unitH = dispH / 100;                          // 人物高度也按图比例 → 缩放时等比
```

**改坐标时**：给背景图叠一层网格标定线（Pillow 画即可）量出店铺位置，
换算成背景图百分比填进 `data.js`，**不要凭肉眼估**。
（标定图不用留在项目里，画完即用。）

另外：角色立绘若要重新抠图，**必须从原始生成图重跑**，
不要对已抠好的 PNG 再抠一遍——会把透明区当背景抠坏。
当前这批的抠图脚本：`_verify7/extract-roles.py`（品红度算 alpha + 前景色反解去溢色 +
每人取最大连通域剔除名字文字），源图是用户的六人合图（品红底 1536×1024）。

当前坐标（背景图百分比，**2026-10 校准器版**：用户在 `../站位校准器/` 里逐人拖动确认，
app.js 的 layout() 带 `hPx*0.0092` 鞋底压线补偿——校准渲染与此一致，
若去掉该补偿六人会集体悬空 ~2px）：

|---|---|---|---|---|---|

| carpenter | 27.00 | 85.28 | 22.5 | r | 青岛木工坊 |
| barber | 36.85 | 76.22 | 14.6 | c | 老城理发室 |
| skewer | 68.94 | 82.48 | 18.9 | c | 老青岛串串香 |
| tuina | 79.51 | 83.80 | 25.0 | l | 中医推拿拔罐 |
| fruit | 87.00 | 98.52 | 26.5 | l | 胶东水果店 |

### 1.1 换背景的操作清单（2026-10 换到 1672×941 后新增）

背景从 1360×768 换成 **1672×941** 时，**四类东西必须一起改**，漏一个就出 bug：

1. `assets/bg-street.jpg` —— **沿用同名**，四处引用（`bgLayer` 的 `<img>`、
   `.intro::before` / `.finale .finale-bg` 的注入样式、`.loader-bg` 的 `../` 相对路径）都不用改；
2. `app.js` 里的尺寸回落值：`naturalWidth || 1672` / `naturalHeight || 941`（共 2 组，4 处）；
3. `data.js` 六人的 `px / py / ph`（见上表）；
4. `app.js` 的 `LEAVES`（树叶锚点）与 `SPARROW`（麻雀锚点）——
   它们同样锚在背景图百分比上，不重标就会飘在空中。

**标定方法（别用肉眼读网格，会连错两轮）**：沿角色所在的竖列（±1.2% 图宽）
扫**亮度剖面**——店铺内部是深色（亮度 < 95），石板人行道是"亮且低饱和"
（亮度 > 118 且饱和 < 70），两者之间那条"由暗转亮"的边界就是能站人的地面前缘。
换图后跑一遍，得到新的 `py` 表。

换完必须回归：三档视口下把渲染像素**反算回背景图坐标**，`py` 应与 `data.js` 完全一致；
`px` 允许被"横向钳制"推开（靠边角色为了让气泡进画面而内移），那是设计行为不是 bug。

### 2. 藏 → 点击走出

用 CSS `clip-path` 实现，**视觉与命中区必须分离**：

```
.hotspot     完整尺寸，负责点击 —— 绝对不能加 clip-path，否则命中区被裁掉难点中
  └ .char-wrap   定位，pointer-events:none
      └ .char-vis clip-path 裁剪，只管视觉
          └ .char-img
```

初始 `--hidden: 100%`（完全不可见，只留呼吸灯）→ 点击后 `.out` 类。

### 2.0.1 呼吸灯：坐标可自定义（2026-10 晚）

呼吸灯从人物盒子里**搬出来**，成为 `hit-layer` 的独立节点 `.ping-zone`。
原来 `.ping` 锁在 `.hotspot` 内（`left:50% / bottom:.5%`），位置被立绘死死绑住，
想让它落在店前台阶、花坛边、路灯下都做不到。

- **坐标字段**：`data.js` 里每个角色可加 `ping: [x, y]`（**背景图百分比**，
  与 `px/py` 同一套坐标系）；不写就自动落在人物脚下（`px/py`），旧数据不出错。
- **尺寸**：`app.js` 的 `PING_SIZE = 4.7`（占背景图高 %，≈ 原 44px），
  按视口等比缩放，`layout()` 里写入。**该常量必须早于 `layout()` 首次执行声明**，
  否则抛 TDZ、整个 IIFE 中断（同类坑已踩过两次）。
- **层级**：`.ping-zone` z-index 3 —— 门面(1) 之上、人物(4) 之下。
- **命中**：★ 2026-10 定案后，`pickHotspot` **只认它**（详见 §2.1）。
- **点亮即灭**：`archive()` 给对应 `.ping-zone` 加 `.gone`。

**当前灯位（2026-10 用户亲自校准，背景图百分比）**：

| 角色 | ping `[x, y]` | 说明 |
|---|---|---|
| cobbler | `[12.20, 88.70]` | 灯心比脚底（92.69）略高，落在人前石的亮处 |
| carpenter | `[27.50, 84.60]` | 与脚底（85.28）基本重合 |
| barber | `[36.85, 76.22]` | 与脚底一致 |
| skewer | `[68.94, 82.48]` | 与脚底一致 |
| tuina | `[80.20, 85.90]` | 比脚底（83.80）低约 2%，落在门口台阶前 |
| fruit | `[87.00, 98.52]` | 与脚底一致；**贴屏幕下沿**，见 §2.1 的可见性说明 |

**定位工具**：仓库根目录的 `呼吸灯定位器.html` —— 双击即开，拖灯圈定位置、
`G` 看人物立绘参照、`Z` 看门面区、方向键微调 0.1%（`Shift` 为 1%），
输出可直接粘进 `data.js` 的 `ping: [x, y]`。

**★★ 灯的绘制分层（踩过一次，务必照做）**：

```
.ping-zone        热区盒子，透明
  └ .ping         坐标容器，pointer-events:none，【不得带 opacity / filter 动画】
      ├ ::before  常亮暖晕（pingHalo：opacity .62 ↔ 1，scale .92 ↔ 1.06）
      └ ::after   向外扩散的涟漪环（pingRing：scale .5 → 1.45，opacity .55 → 0）
```

伪元素是 `.ping` 的**子层**，父级 `opacity` 会与子层**相乘**。
原来把"涟漪淡出"（`.55 → .16 → 0`）直接写在 `.ping` 上，
涟漪淡到 `.16` 的那一瞬，里面那点常亮暖核也被压成 `0.95 × 0.16 ≈ 0.15`
—— 整盏灯等于消失。当时以为是"配色太淡"，其实是乘法。
**结论：容器透明静止，涟漪与暖晕各自独立动画，互不压制。**

暖晕强度 **2026-10 晚再调亮一档**（应要求"亮度调高、明显一点"）：
渐变内圈加浓（中心纯暖白、38% 处 .72）、外圈双层辉光 22px + 44px、
涟漪环加粗到 2px。实测（1920×1080，鼠标停在顶部避免视差）
逐灯"开灯 / 关灯"两帧差分：亮度贡献峰值从 74~164 提到 **301~611**，
明显变化像素 1000~2900 px² —— 石板路上一眼可见，但仍未过曝。
想让灯更抢眼或更收敛，只改 `.ping-zone .ping::before` 的渐变 alpha 与尺寸即可。

入场动画（2026-10 晚「轻触唤醒」版）已从 clip-path「长出来」换成
**`fadeDevelop` 0.7s 显影**：opacity + 微 blur + 6px 位移，像老照片逐渐显影；
动画只作用于 `.char-vis`，元素位置不变（脚底不飘）。

### 2.1 命中判定：只认呼吸灯（2026-10 晚第二批要求，最终定案）

`pickHotspot(x, y)` 现在**只做一件事**：把所有 `.ping-zone` 里套住这个点的挑出来，
返回 DOM 里最靠后（画在最上层）的那盏灯对应的角色；其余一律返回 `null`。

```js
function pickHotspot(x, y) {
  const pings = [...hitLayer.querySelectorAll('.ping-zone')].filter(z => {
    if (z.classList.contains('gone')) return false;          // 已唤醒的灯不再响应
    const r = z.getBoundingClientRect();
    return x >= r.left && x <= r.right && y >= r.top && y <= r.bottom;
  });
  if (pings.length) return hotspotEls[pings[pings.length - 1].dataset.role];
  return null;
}
```

**为什么砍掉「人物 alpha 判定」和「店铺门面兜底」两条旧路径**（它们曾经存在，
现在连代码一起删了，避免留下互相矛盾的判定）：

1. **语义唯一** —— 画面里初始唯一可见的线索就是那圈暖光。
   "点灯＝唤醒" 与画面对得上，不会误导；再说"点击店铺"就自相矛盾了。
2. **视差下最稳** —— 灯的命中区小而实（≈44px 圆），
   不像立绘大盒子那样容易与邻居重叠、抢走本该落在别人身上的点击。
3. **原「点不动」的两个真因都已消失**：视差阻尼早提到 `0.16`（收敛 ~0.25s），
   且不再需要单像素 alpha 判断 —— 灯的盒子判定对几十毫秒的漂移天然免疫。

**⚠️ 顺手修掉的一个隐藏 bug（改这块时一定会再遇到）**：
`.scroll-rail`（底部那根 4px 的滚动导轨，`z-index: 20`）横跨屏幕底部，
会压在**贴地那盏灯**（王姐，灯心 y≈98.5%，即屏幕下沿）之上 ——
点在灯上的那一小段，`elementFromPoint` 返回的是 `.scroll-thumb`，
而点击监听挂在 `#hitLayer` 上，事件根本不经过它 → **灯点不动**。
修法：`.scroll-rail { pointer-events: none; }`（它本来就是纯指示条，没有任何 JS 交互；
拖动街景的 `pointerdown` 挂在 `#stageWrap` 上，穿透后照旧生效）。

**灯心贴下沿的可见性**：王姐那盏灯在 1920×1080 下的中心落在 y≈1081（视口高 1080），
即**只看得见上半圈**（约 50% 面积）。这是用户校准坐标与「背景图 cover + 轻微放大裁切」
共同决定的，属实正常：**可见的那半边照样点得开人**，验证脚本也按"可见部分中心"取落点。

**连着失效的连带规则**：`layout()` 里老的「热区永不重叠」左→右推挤、
`hotspotEls` 必须写 `.hotspot[data-role=...]`（防 `.shop-zone` 污染 `data-role` 选择器）、
空处光斑排除 `.shop-zone` —— 这三条仍要保留，因为 `.shop-zone` 节点还在（只是不再参与命中），
选择器污染与光斑误闪的坑依旧会踩。


### 2.2 窄屏平移范围（2026-10 修）

`updatePanRange()` 原来按 `dispW - w` 算可拖范围，默认图片**左对齐**——
但 cover 是**居中**裁切，图比舞台宽时左右各溢出一半。
旧算法只允许往左拖 → 最左边的店铺（修鞋铺）在任何视口都永远拖不回来。
正确范围：`minPan = w - cropX - dispW`（看到图右缘），`maxPan = -cropX`（看到图左缘）。

### 3. 气泡自动避让

相邻角色 x 间距常常小于气泡宽度（238px），靠固定错落层必然连环冲突。
`layout()` 里实测每个气泡矩形，自动上移/下移避让（`--bub-y` 手工值已废弃）。

**注意**：`.hotspot` 带 `transform: translate(-50%,0)`，
会成为绝对定位子元素的**包含块**——气泡的 `top` 是相对**热区顶边**的，不是相对舞台。
比较重叠时要换算：`stageTop = top + relTop`。

**水平钳制（2026-10 修，接地版再修）**：靠边的角色原先只把**身体**夹进画面、没算气泡，
1440 宽屏下 cobbler 的气泡左边被切掉 28px（1280 下切 38px），fruit 右边同理。
现在统一用 `need = max(身体半宽 + 2, 气泡半宽 + 6)` 对人物中心做一次钳制。
靠边角色为露出气泡会略微移出画面 ——"看得见台词"比"半个身子"重要。

接地版的三条新约定：

1. **气泡半宽用恒定设计值 `BUB_HALF = 121`**（max-width 238 的半宽），**不要实测**：
   未点亮时气泡是空的、宽度为 0，实测会让点亮前后的 `need` 变化 →
   人物在点亮瞬间整体跳位。恒定值保证布局稳定。
2. **推挤 vs 画面边界的仲裁**：被钳制的角色先按邻居间距往右推，
   再帽回画面内（气泡可见优先）；但帽回**不能把已放好的邻居吞掉超过其身宽 60%**
   —— 414 下无脑帽回会让 fruit 完全盖住 barber（最上层不透明像素全归 fruit，
   点不到）。吞超了就放在「恰好吞 60%」的位置，宁让气泡框探出画面十几像素。
3. **验证口径**：脚底用局部坐标反算（`screen → local` 要**只用矩阵线性部分求逆**，
   `panX`/视差平移已含在 hit-layer 盒子原点里，整矩阵求逆会重复扣一遍）；
   气泡对「整个人都在初始画面内」的角色要求绝对不出画，
   对需要拖动才能看全的角色只要求气泡以人物为中心能装进一屏。

**单人水平偏移 `bubDx`（2026-10 晚新增）**：王姐在最右端，
她与林姐的气泡挤在一起（王姐的框会压住林姐的立绘），
`data.js` 里给她加了 `bubDx: 5.2`（背景图宽度的百分比）。
`layout()` 把它换算成 px 写进 `--bub-dx`，CSS 用
`left: calc(50% + var(--bub-dx, 0px))` 生效，**避让算法读的是同一个偏移量**，
所以"气泡对不准人物 / 避让算错位置"不会发生。
只改 `data.js` 的 `bubDx` 即可微调，不必动通用定位逻辑。
（实测 1920 下王姐气泡左边距林姐立绘右缘 **+171px**，无重叠。）

### 4. 背景层与人物层同步变换

`applyParallax()` 给 `bgLayer` 和 `hitLayer` **完全相同**的 transform。
只给背景加变换、人物不动 → 鼠标一动就错位。
也**不要加 `scale()`** —— scale 会让坐标换算失准，只留 translate。

### 5. 开场页（第一屏）与三处易踩的坑

**第一屏只有一页**（原第二幕 `.intro` 卡片已删除，文案与按钮都并进了 `.loader`），
结构是**上中下三段，互不重叠**：

```
38%  题献「记忆里的那条街」＋ 其下英文小字 MEMORIES OF AN OLD STREET
     ← 星尘聚成的唯一主角，粒子演完停在这里
54%  一道细金线
62%  起 大标题「街角记忆」· 店名 · 说明 · 【走进这条街 →】
底部  一行小字「点击任意处，直接走这条街」
```

两条铁律：**① 任何两段之间至少留 6vh，绝不允许叠字；② 起手必须暗 —— 亮起来只发生在用户点击之后**
（`.loader-bg-top` 初始 opacity 0 + 近全黑，只有 `.entering` 才跑 `bgFocus`）。

**第一屏绝不自己往前走**：`loader-fx.js` 演完只加 `.armed` 就停，**不 dispatch 任何"结束"事件**；
`app.js` 的 12s 兜底**只 `arm()` 不 `enterStreet()`** —— 进不进永远由用户决定。

**坑 1 · `background` 简写会覆盖注入的 `background-size`（曾导致整页糊成一片）**
CSS 里的 `url()` 会相对 `css/` 解析，所以凡是用 JS 注入背景图的层，**只能注入 `background-image`**。
如果注入的是整条 `background` 简写，就会把 CSS 里的 `center / cover` 一起覆盖成 `size:auto`
—— 背景按原图像素绘制、不再铺满，再叠上 `blur()` 与 `scale()`，整屏只剩一片糊色，看不出街道。
**约定：尺寸一律写在 CSS 里。**（第一屏的两层底现在都用 `../assets/...` 相对路径，不走 JS 注入。）

**坑 1b · 粒子字与真字必须共用同一套排版参数**
粒子取点是 canvas 上按 CSS 的 `font-size` / `letter-spacing` / `font-weight` / `font-family` 量出来的，
所以 JS 里必须复刻同一套公式（`titlePx()` / `titleLs()` / `FONT_STACK` / `TITLE_Y_RATIO`）。
少同步一项就会出现「粒子字 + 真字」两行叠着 —— 这是"排版撞车"最隐蔽的一种。
实测（1920 宽）：中心差 dx=2px、dy=1.4px、宽度差 2.5%（步长 3 取整的必然零星误差）。

**坑 2 · `layout()` 的早调会踩 TDZ（曾让整页失效）**
`app.js` 里 `if (bgImg.complete) layout();` 在**背景图已缓存**时是同步执行的。
`layout()` 内部会读 `hotspotEls`、`maxPan` / `panX`，结尾还会调 `applyParallax()`
读 `curTX` / `curTY`，而这些 `const` / `let` 原先声明在后面 →
抛 `Cannot access '…' before initialization`，整个 IIFE 中断：
加载页不消失、人点不动、`window.StreetCorner` 也不存在。
**冷启动（图片没缓存）不复现，只有刷新/二次访问才炸。**
现在的顺序是：1.1 热区节点表 → 1.3 平移状态 → 1.4 视差状态与 `applyParallax` → 建热区 → 首次 `layout()`。
**新增任何被 `layout()` / `applyParallax()` 读取的 `let`，都必须声明在这次首调之前。**

**坑 3 · 第一屏期间要藏掉街道页的控件**
`.app.booting`（写在 `index.html` 的 `.app` 上，点「开始走这条街」后由 `app.js` 移除）
把 `.hud`（音乐 / 重走两个符号钮 / 0-6 进度）和 `.stage-hint` 隐藏 —— 它们都是
"已经开始走这条街"之后才有意义的东西，出现在第一屏只会抢注意力。

### 背景音乐（2026-10 晚）

`assets/audio/bg-street.mp3`（木琴 + 街道车流，80s 循环），开关是 HUD 左上角的
`#musicBtn` —— 半透明磨砂圆钮 + 内联音符 SVG + 三根随节拍起伏的声波，
与「重走」同一套符号钮语言（**第二批改版后 HUD 上不再有文字纸签**）。

- **音量默认 12%**：与作者试听时播放器上的音量一致。背景音乐的职责是垫底，
  人说话的声音必须始终在最前面。用户之后调过的值存 `jiejiao_bgm_vol`，下次沿用。
- **起播时机**：浏览器不允许无手势出声，所以真正的 `play()` 挂在
  `enterStreet()` 里那一下点击（全站第一个用户手势）。`preload="auto"` 只预载不播，
  `autoplay` 属性刻意不加。
- **淡入淡出用 `setInterval` 阶梯（40ms 一档），不是 rAF 插值**：
  音频时钟与 rAF 不同步（后台标签页、无头环境里 rAF 会被节流甚至停摆），
  用 rAF 会出"在播但 volume 恒为 0"的哑声。
- ★ **淡出结束必须归 0，且顺序是"先开闸、再赋值 0"**：`volumechange` 是**异步派发**的，
  浏览器何时把事件交给监听器不严格可控；反过来写会把 `0` 当成"用户设定的音量"存进
  localStorage，之后每次访问都是静音。同时 `volumechange` 里要挡掉 `<= 0.001` 的值。
- **切后台自动暂停**，回前台走 `play()` 而不是裸 `audio.play()`（后台暂停时音量已归 0，
  裸 play 会"播放但听不见"）。
- 音乐按钮就是普通 DOM 按钮：放大镜退役后（见 6.1b），全站只有一枚 CSS 三角光标，
  不存在"镜身压住图标"的问题。

三条写脚本时踩到的口径坑，改脚本前务必先读：

1. **不能用「整屏平均亮度」判断星尘可见** —— 暗底占绝大多数像素，平均必然被拉低。要量**亮像素自身的平均亮度**。
2. **粒子相关断言不能用固定 `waitForTimeout(ms)`** —— 粒子要等 `document.fonts.ready` 才 boot，要轮询到「画布有像素」。

   `.armed` 刚触发的瞬间（`waitForFunction` + `polling:'raf'`）采样，且这个采样要放在**独立 page** 里，
   免得打乱主流程的相对等待。
